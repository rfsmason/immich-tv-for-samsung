# 0021 - Support Us

## Context

Immich TV is free and MIT-licensed. The user wants people who enjoy it to be able to tip voluntarily, without the app changing because of it: nothing is unlocked, and there are no prompts, countdowns, nag screens or pop-ups. The Milestone 8 splash notes already planned a quiet support line pointing to a Settings area, and a thank-you instead once the user has supported the app.

The app reaches people two ways. Today it is sideloaded onto TVs in Developer Mode. Later it may be published in Samsung's TV app store, where Samsung's own in-app payment route is Samsung Checkout: a Billing API that shows Samsung's purchase screens, with products registered in Samsung's Digital Product Inventory and purchases verified through its server APIs ([Samsung Checkout](https://developer.samsung.com/smarttv/develop/guides/samsung-checkout/samsung-checkout.html), [Implementing the Purchase Process](https://developer.samsung.com/smarttv/develop/guides/samsung-checkout/implementing-the-purchase-process.html), [Billing API](https://developer.samsung.com/smarttv/develop/api-references/samsung-product-api-references/billing-api.html)).

## Decision

- **A tip page, not a payment.** The tip page is `https://ko-fi.com/immichtv`, with no tracking parameters. The TV never pays and never contacts Ko-fi: it shows a QR code and the short address `ko-fi.com/immichtv`, and the user tips on their phone. Suggested tips are £5 (a coffee), £10 (lunch) and £20 (dinner); any amount is welcome.
- **Sideload builds only.** Support Us and the splash's support line exist only in sideload builds, which are the default. A store build carries no tip link, QR code, Support section or splash line. How Samsung's store review treats an outside tip link is untested, and Samsung Checkout is Samsung's documented route for payments in a store app, so a store build leaves the link out entirely rather than relying on it being acceptable. If tips are wanted in the store later, they go through Samsung Checkout, with its own ADR.
- **The build flag.** `scripts/build-app.mjs` builds `sideload` unless `--store` or `IMMICH_TV_DISTRIBUTION=store` asks for a store build (`npm run build:store`; `IMMICH_TV_DISTRIBUTION=store npm run tizen:package`). `scripts/build-options.mjs` holds the choice and the esbuild options, passing the distribution to the bundle as `__IMMICH_TV_DISTRIBUTION__` through esbuild's `define`.
- **One reader.** Only `src/app/distribution.ts` reads the define; it exports `distribution`, `supportPage` (the tip page, or null) and `supportLinksEnabled`. The composition (`main.ts`, `application.ts`) passes `supportPage` to Settings and `supportLinksEnabled` to the splash, so screens never read the build flag.
- **Dropped, not hidden.** esbuild folds a define only where it is written and tree-shakes before it inlines constants across modules, so `distribution.ts` selects the tip page with the define itself: in a store build the condition folds to false, the tip page module is never referenced, and minification drops its link and QR code. The link and QR live in TypeScript (`src/screens/settings/support-qr.ts`), never in `index.html`, so the static files have none either. The Support section's code without the link stays in a store bundle, unreachable. A store-build test (`scripts/build-options.test.mjs`) and `IMMICH_TV_DISTRIBUTION=store npm run check` fail if a store bundle, its static files or the staged package mention `ko-fi`.
- **Settings › Support Us.** A `support` section in the `SettingsSection` pattern, after Ambient and before Save and Exit, with a heart icon. Its button and panel are built from TypeScript, so a store build has no button, gap or dead focus target. The panel has a heading, a short line saying the app is free and tips unlock nothing, the tips, the QR code with "Scan with your phone" and the address, and the toggle "I've already supported Immich TV". The toggle is the panel's only control; rail movement, Back, Save and the unsaved-changes guard work as in every section.
- **The QR code.** It encodes exactly the URL, at error correction M (version 2, 25 × 25 modules) with a four-module quiet zone. It was generated once with macOS Core Image's `CIQRCodeGenerator` through `scripts/support-qr.swift`, so the project gained no dependency, and is stored as an SVG path. It is drawn 360 px square, black on a white tile in every theme with `shape-rendering="crispEdges"`, `aria-hidden` and not focusable. Like a photo it is media, so its two colours are listed as media-only in `scripts/contrast-rules.mjs`. A rendered screenshot decodes to exactly the URL with Core Image's `CIDetector`.
- **The honour toggle.** `AppSettings.supporter` (default false; settings schema version 5, where a version 4 file loads unchanged with the toggle off) records that the user says they have tipped. It is taken on trust: nothing is checked and nothing is unlocked; it only changes the splash's line.
- **The splash line.** Sideload builds show "Free to use. You can support development in Settings." or, for a supporter, "Thank you for supporting Immich TV." Store builds show no line. `src/screens/splash-support.ts` sets it from the settings startup already restores, before the splash's first paint, with no wait, request or focusable element; it replaces the old static "Free to use. Supported by people who enjoy it." After a save the line is updated, and shows the next time the splash does.

## Consequences

- Sideload users can tip from the sofa with their phone, and the TV stays a viewer that never handles money or talks to a payment service.
- A store build must be asked for explicitly; packaging and deployment defaults stay sideload. A store package built by mistake as sideload would carry the link, so store submission should use `IMMICH_TV_DISTRIBUTION=store npm run tizen:package` and `IMMICH_TV_DISTRIBUTION=store npm run check`.
- The supporter toggle can be turned on by anyone; that is intended, since it unlocks nothing.
- Changing the tip page means regenerating the QR code with `scripts/support-qr.swift` (macOS) or another encoder, updating `support-qr.ts` and the website's QR asset, and decoding the result again.
